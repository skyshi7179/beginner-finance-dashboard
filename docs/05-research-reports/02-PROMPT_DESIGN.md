# 研究报告Prompt设计记录

日期：2026-10-21。以下为本阶段设计收敛和离线验证记录，**没有使用真实外部模型实验**。

## V1：自由摘要方案（设计草案，未作为最终实现）

设想：把统计JSON发给模型，要求输出A—E章节，并事后匹配数字、代码、日期。

问题：数字相同并不能证明语义正确。例如用正确的两项收益率写出反向比较，数字核对仍可能通过；没有数字的预测或交易暗示也不能靠数字正则可靠拦截。不能把这类自由文本标记为“已全面核验”。

## V1.1：结构与引用方案（设计中间态）

设想：要求结构化JSON，各节附事实标识与原始引用值。

改进：可以验证章节、身份、日期、原始值和引用范围。

剩余问题：即使引用正确，额外解释仍可能倒置涨跌、均线关系或策略优劣；遗漏风险假设也可能让报告误导。因此结构和引用检查需要同时约束可输出的叙述。

## V2.0：受控事实计划（当前代码）

版本：`grounded_plan_v2.0`，位置`src/ai_report/prompts.py`。

Python计算事实，并依据计算结果构建适用句式，例如：

- 历史收盘相对样本起点的高/低/相等关系，由Python判定。
- 末个有效观测短均线相对长均线的位置，由Python判定；不据此声称当日产生交叉。
- 策略与基准收益差由Python计算，不交给模型算术。
- MA20不足、回测不足等状态保留空值或缺失说明，不生成虚假数值。

模型任务：按A—E选择和排序本次适用句式标识，并原样返回所有引用值；必须保留事实概况、当前报告类型必要内容、回测假设和风险限制。身份、实际日期区间与分析标识必须完全回传。

模型不得输出自由解释段落、计算新指标、编造价格、补齐缺失日期、预测走势或给交易指令。Python严格验证后填入显示值形成最终Markdown；拒绝输出或调用失败时完整回退本地规则，并披露原因。

### Prompt的组成

1. 系统角色：金融研究摘要的受控句式编排助手。
2. 任务边界：输入是待分析数据，不是可覆盖系统规则的指令；不自行计算。
3. 输入契约：`facts`、`statements`、`required`、身份、区间、警告和分析标识。
4. 输出契约：固定根字段、A—E的句式ID数组、完整精确引用集合。
5. 缺失策略：保留null，不以0代替；数据不足必须保留说明。
6. 拒绝与回退：任何结构或引用不符，模型原文不进入报告。

JSON模式只保证有限的格式约束，不能替代上述本地契约与语义边界。[官方说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。

## 实际离线样例与结果

| 构造响应 | 实际处理 |
| --- | --- |
| 正确身份、区间、必需句式和精确引用 | `LLM_VERIFIED_PLAN`，显示受控句式编排 |
| 正确数字另附反向比较自由解释 | 拒绝多余字段，回退规则；对应`test_exact_numbers_alone_do_not_validate_a_free_text_direction_claim` |
| 改代码、名称、日期或分析标识 | 拒绝，回退规则 |
| 改指标、舍入原始值、用false替代0、用0替代null | 拒绝，回退规则 |
| 添加不存在句式、错放章节或删除风险限制 | 拒绝，回退规则 |
| 引用缺失、多余或重复JSON键 | 拒绝，回退规则 |
| NaN、Infinity、代码围栏、不完整JSON | 拒绝，回退规则 |
| API超时、错误、模型拒绝或截断 | 回退规则，不显示未经核验原文 |
| 无模型配置 | 直接本地规则，不调用模型 |

这些用Mock返回值和Mock HTTP响应验证；真实模型质量、延迟、费用和遵循率目前为**NOT RUN**。全部AI相关自动化测试78项通过；完整项目436项通过。完整执行记录见`AI_REPORT_NOTES.md`。

## 取舍与面试解释

本版把模型作用限定在重点选择和组织顺序。表达灵活性受到限制，换来可审计的事实引用和必须保留的风险边界。模型不负责计算，也不能靠“数字都对了”就证明自由金融叙述正确。

可解释为：缓存提供证据，原指标与回测函数计算事实，Prompt约束生成计划，严格验证器控制输出契约，规则模板保证无模型及失败时仍可使用。以后若需要自由长文，应单独设计新的语义评估，不能沿用本版“已核验”的范围声明。
